# 开工约定

本项目用 coperate 规范管理文档。动手之前，先做三件事。

## 1. 读这两个文件

- `docs/M-005-协作规范.md` —— 唯一约束你行为的文件：依据优先级、冲突处理、汇报格式、绝对不许做的事
- `docs/M-003-技术方案.md` —— 目录结构、命名规则、锚点与校验规则

**不要拿 `work/` 下的东西当依据。** 那是过程产物，只记录「当时怎么想的」，不是「现在怎么做」。

## 2. 开工前跑一次校验

```
python tools/scan.py
```

有「必须修」就先修，不要带着断链继续往上加东西。

## 3. 改完必须重跑生成

```
python build.py
```

人只看 `BOARD.html`，不看 `.md`。产物是给你读的，页面是给人看的。

## 4. 开工时先报待办

`TASKS.md` 里有未完成项时，先列出来问一句要做哪个。不要自己挑一个开始。

## 这几个文件不要手改

`build.py`、`tools/scan.py`、`AGENTS.md` 是项目之外的东西，升级时会整体覆盖。

要改逻辑，去规范项目改，再 `--sync-tools` 同步过来。

## 这个文件不重复细则

上面四条是**动作**，不是**规则**。规则只有一份，在 M-005 里。

这里刻意不抄一遍——抄了就有两份，两份迟早不一致，而且不一致的时候没人知道该信哪份。
