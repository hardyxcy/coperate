# M-002 玩法与范围

## 一、核心循环 {#loop v1}

待补。玩家反复做的那一个动作是什么？一局多久？

小游戏的硬指标：**30 秒上手，3 分钟一局。** 超过这个就留不住人。

要写清这条链：开始 → 玩家做什么 → 什么情况下结束 → 为什么还想再来一局。

## 二、操作方式 {#control v1}

待补。点击 / 滑动 / 长按 / 拖拽 / 重力感应。

单手还是双手？微信小游戏绝大多数是**单手竖屏**，设计时必须假设另一只手在扶栏杆。

## 三、规则与失败 {#rules v1}

待补。什么算赢、什么算输、输了怎么重开。

重开成本要极低——点一次就再来，不要回主菜单、不要看广告。

## 四、数值与难度 {#balance v1}

待补。初始值、成长曲线、难度怎么递增。

| 项 | 值 | 说明 |
| --- | --- | --- |
| 待补 | | |

**数值是玩法的骨架。** 没有数值表，做出来的东西手感一定不对，而且改的时候只能瞎试。

## 五、关卡与内容 {#levels v1}

待补。多少关、手工做还是程序生成、内容量够玩多久。

一个人做的小游戏，程序生成的耐玩度通常高于手工关卡。

## 六、美术与音效 {#art v1}

待补。风格参考、色板、需要哪些资源、大致数量。

小游戏的美术不用精致，但必须**统一**。风格不一致比丑更劝退。
